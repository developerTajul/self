## BASE REPOSITORIES (builder version)
Keep the same three-class split as the `$wpdb` bases (03), so the CQRS boundary and every module's `extends` clause survive the swap: `abstract class AbstractWpRepository` holds `newQuery()`; `abstract class BaseWriteRepository extends AbstractWpRepository` holds `createRecord`/`updateRecord`/`deleteRecord`/`findRecordForUpdate`; `abstract class BaseReadRepository extends AbstractWpRepository` holds `fetchAllLatest`/`paginateRecords` and no write method.
`AbstractWpRepository`, constructor (promoted): `protected readonly QueryBuilderInterface $database, protected readonly string $table` (logical name, no WP prefix); child passes a code constant. All helpers `protected`; rows are arrays.
`newQuery(): QueryBuilderInterface` = `$this->database->table($this->table)` (a FRESH builder every call, never reuse one: clauses accumulate) | `fetchAllLatest(): array` | `findRecord(int $id): ?array` | `createRecord(array $data): array` (`insertGetId`, then re-read) | `updateRecord(int $id, array $data): ?array` (update only if a value differs, compare as strings; return the fresh row) | `deleteRecord(int $id): bool` | `findRecordForUpdate(int $id): ?array` (`lockForUpdate()`, inside a transaction) | `paginateRecords(int $page = 1, int $perPage = 10): array{rows,total}`.
Rules: no raw SQL, no `$wpdb`, no raw-expression escape in any repository; every value is a binding; table/column names are code constants; a capability the builder lacks is a JOB F task (HALT), never a bypass. Read adapters inject `QueryBuilderInterface` and start every query with `table()`. Inject the interface, never a static facade. Rows may be strings: cast in `toEntity()`.
